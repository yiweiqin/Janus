# uBuddy V4 主张冻结（阶段 0）

> 状态：已冻结，供阶段 1 方案稿与后续训练协议引用。  
> 日期：2026-09-10  
> 配套方案稿：[ubuddy-pain-points-innovations-v4-self-evolution.zh-CN.md](ubuddy-pain-points-innovations-v4-self-evolution.zh-CN.md)  
> 本文只钉口径。实现、标注和训练不属于本阶段。

V3 及更早主线把依赖集束同时用于跨人信息流通、最小披露和联合进化。V4 把主痛点收束为跨人任务组织个体的**可归因自进化**；跨人看见什么改由任务公共 memory 解决；依赖集束只保留选人、换人和能力差归因。

---

## 1. 冻结的问题陈述

> 在跨人、跨组织、多 Agent 任务中，如何让参与者默认只使用同一份任务公共 memory 的基础层与提升层进行协作；并在规划理想路径与现实可执行路径出现差异后，用反向侦探找到最小漂移，用能力画像依赖集束做最小能力改动的替换实验，从而把组织规划、个体能力和协作边的更新限制在有对照证据的最小改动上？

一句话版：

> 公共 memory 回答看见什么；方案一回答偏在哪；方案二回答找谁、换谁、差在哪项能力。

---

## 2. 冻结的痛点

只保留一个主痛点，两个可测子问题。V3 的 P1（静态披露两难）和 P2（公共状态动作不稳定）不再作为当前研究痛点。

### P_evo：跨人任务组织无法准确自进化

成功或失败往往是长链路的共同结果。若只看最终验收，系统会把责任派给末端 Agent，或把一次补救路径整段写进长期策略。跨人场景里，规划来自组织拆解和协作选择，执行来自真实约束、改派和局部重规划，两者本来就会分叉；没有最小漂移定位和最小能力改动实验，组织、个体和协作边会被一起改错。

#### P_drift：规划路径与现实路径的差异找不到最小漂移源

规划树记录 AI / 组织认为应该怎么做；执行树记录实际可走的路。差异可能来自漏依赖、错 Agent、错版本、错验收或中途重规划。需要的是那个**最小引起后续分叉的节点或边**，不是把所有差异点都当成原因。

#### P_swap：失败后不知道该换谁，也无法把结果差归因到具体能力差

随机换人或只按历史总分换人，会同时改变多项能力，无法判断究竟是哪一项细节导致结果变化。需要在能力画像上把“谁该一起协作”和“失败后谁最像原 Agent”分开。

测量对象：

- 最小漂移定位准确率、冗余归因率、无漂移对照上的误报率；
- 相似替换相对随机替换的归因可辨识性；
- 最小改动后的任务收益、负迁移和回滚率。

不测量：最小披露成本、决策充分证书率、隐私攻击成功率。这些不再是 V4 主指标。

## 3. 冻结的两条方案

### 方案一：规划—执行双树对照与反向侦探最小漂移归因

- 中文名：反向侦探最小漂移（简称：反向侦探）
- 英文名：Reverse-Detective Minimal Drift（RDMD）
- 用途：在观察到规划树与执行树分叉后，定位最小漂移源，供后续决定改组织还是改个体。

| 项 | 冻结内容 |
|---|---|
| 输入 | 规划树 \(G^{plan}\)（或合成数据中的原正确路径）、执行树 \(G^{exec}\)（或注入改动后的路径）、节点/边对齐、结果版本 |
| 输出 | 最小漂移假设：节点或边 ID、漂移类型、证据节点集合；证据不足时 `UNKNOWN` |
| 监督 | 合成样本中预先注入的那一次最小改动（凶手手法已知）；模型只看见两条路径 |
| 不做 | 不当规划器；第一版不直接输出完整修复方案；不把所有差异点都标成原因 |

漂移类型第一版只允许：

```text
missing_dependency | wrong_agent | wrong_version | wrong_acceptance | local_replan
```

多注入、无标答样本只用于测拒答，不进入主监督。

### 方案二：基于能力画像的依赖集束

- 中文名：能力画像依赖集束
- 英文名：Capability-Profile Dependency Bundle（CPDB）
- 用途：规划时选协作对象；执行不佳时做最小能力改动替换；用替换结果归因到具体能力差。

依赖集束在 V4 中是两个**分开保存、分开使用**的分数，禁止合成不可解释总分。

| 分数 | 含义 | 何时用 | 何时不用 |
|---|---|---|---|
| 依赖分 \(D(A,B)\) | A 的产出作为 B 输入的匹配程度（整理→写作高） | 初始规划选协作 | 不用来换人，不当根因分 |
| 相似度 \(S(A,B)\) | A 与 B 的 skill / 任务族接近程度（两个做 PPT 的高） | 失败后替换实验 | 不作首选协作信号 |

| 项 | 冻结内容 |
|---|---|
| 输入 | 两端能力画像、任务类型、历史合作记录（若有） |
| 输出 | \(D(A,B)\)、\(S(A,B)\)、使用了哪类证据 |
| 监督 | 人工可标注的依赖分与相似度；合作成功后依赖分按指数递减加分 |
| 归因实验 | 固定其余条件，用与原 Agent 相似度最高的替代者替换；变好则归因到二者能力差，仍差则转交方案一 |

合作更新规则（冻结）：

```text
D <- D + η · δ · exp(-λ · n_success)
```

其中 \(\delta\) 为本次合作正信号，\(n_success\) 为这对 Agent 已成功合作次数，\(\eta,\lambda>0\)。失败不把依赖分直接打到零，先做相似替换实验。

## 4. 冻结的任务公共 memory

跨人信息流通不再由依赖集束或最小披露求解器承担。任务公共 memory（Task Public Memory，TPM）是该任务的唯一协作记忆。

| 层 | 内容 | 默认可见性 |
|---|---|---|
| 基础层 | 规划图 / 规划树、执行图 / 执行树、节点状态、版本、结构依赖边 | 本任务参与者可见 |
| 提升层 | 经系统省检后的摘要：里程碑、结果版本、阻塞、验收、风险提示 | 本任务参与者可见 |
| 原始层 | 完整对话、完整文件、完整中间产物、未脱敏上下文 | 默认不可见；跨任务更不可见 |

可见性规则：

1. 本任务执行默认只展开基础层和提升层。
2. 其他任务若要本任务原始层，必须提交申请，不能自动拉取。
3. 省检只写入提升层；失败的条目不进提升层，也不偷偷写入基础层。
4. 原始层申请：申请单 → AI 预审 → 通过后再交任务 Owner 终审 → 短时、可审计、可撤回的只读授权。

审查机制是工程门禁，**不是** V4 研究贡献。

## 5. 冻结的自进化对象与门禁

可更新对象只有三类：

```text
组织规划策略（拆分、依赖、验收、模板）
个体能力（画像、Skill、工具策略）
协作边（依赖分；相似度相对稳定，不因单次成败大改）
```

门禁：

1. 单任务成功或失败只记诊断，不写长期策略。
2. 没有对照实验（相似替换或结构最小改）不更新。
3. 更新必须带适用范围；出现负迁移则回滚或降权。
4. 方案一定位漂移在能力，才走方案二替换；漂移在结构 / 依赖 / 验收，则最小改规划，不换人。

## 6. 非主张清单

当前不得声称：

1. 最小披露、决策充分投影或 `CERTIFIED` 是 V4 主创新。
2. 系统能识别真实私有世界。
3. 依赖集束总分等于因果根因。
4. 依赖分决定换人，或相似度决定初始协作。
5. 原始层审查是算法贡献或已验证的安全证明。
6. 生产环境中的自进化已经被实验证明。
7. 规划树应机械复制成功执行树。
8. 反向侦探在无注入标答的真实任务上已经达到因果正确。

V3 的 TDB 十维后验、finite-world 披露 solver、投影训练头保留为历史实现，不作为 V4 论文主线继续扩张。

## 7. 术语对照

| V4 术语 | 含义 | 与 V3 的关系 |
|---|---|---|
| 任务公共 memory | 任务级三层协作记忆 | 取代最小披露作为跨人信息流通机制 |
| 规划树 \(G^{plan}\) | 执行前冻结的理想 / 计划路径 | 沿用全链路规划树，进入基础层 |
| 执行树 \(G^{exec}\) | 真实事件形成的可执行路径 | 沿用执行图，进入基础层 |
| 反向侦探 | 由双树差反推最小漂移源 | 取代 TDB 后验 + Probe 证书作为主归因叙事 |
| 依赖分 | 协作匹配，用于规划选人 | 不再表示“当前边能否支持下游决策” |
| 相似度 | 能力邻近，用于换人实验 | V3 几乎未作为独立分数 |
| 能力画像依赖集束 | \(D\) 与 \(S\) 的统称 | 旧 TDB 状态对象降级，用途收窄 |
| 最小漂移 | 能解释后续分叉的最小注入点 | 不是全部差异点的集合 |
| HDBP / 最小披露 / CERTIFIED | 历史术语 | 不进入 V4 主贡献 |

## 8. 与 V3 三模块的映射

```text
V3 模块一 部分可观测世界 + TDB-plan
  → V4 基础层（规划树 / 执行树）+ 能力画像
V3 模块二 最小充分披露
  → 删除主创新；信息流通改走 TPM；审查进工程附录
V3 模块三 反事实联合进化
  → 拆成方案一（定位）+ 方案二（选人/换人/能力差）+ 门禁
```

现有可复用底座（不视为 V4 已实现）：规划图 / 执行图、Work Memory、能力画像快照、计划—执行对照接口。
