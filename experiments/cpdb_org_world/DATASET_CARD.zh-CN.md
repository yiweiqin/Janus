# 组织世界数据集卡（cpdb_org_world_v1）

## 要训什么

第二份同规模 8B QLoRA 学两件分开的事：

- 依赖分 \(D(A,B)\)：A 的产出是否适合作为 B 的输入，用于一开始规划选协作。
- 相似度 \(S(A,B)\)：A 与 B 的能力是否邻近，用于执行不佳时做最小能力改动替换，从而把结果差归因到少数细节能力。

人工可以直接看两张能力卡片打分。合作成功后的指数递减加分不进入相似度主标注。

## 世界规模

| 对象 | 数量 |
|---|---|
| 组织 | 12 |
| 人 / uBuddy | 120 |
| 每人 specialist | 5 |
| Agent | 600 |
| 初始配对 | 8282 |
| 切分 | train 6705 / development 778 / test 799 |

每个 specialist 有职能（信息整理 / 数据清洗 / 文案 / 演示 / 代码 / 验收）和一项细节能力面（来源分级、年份窗口、品牌语气、图表层级、接口钉死等）。同一人内部以互补为主，并保留一个近邻替换位；跨人保留同职能不同细节的 twin，供替换实验归因。

## 画像

- Agent 画像：由其 Skill 直接生成，含 `capabilityTags`、`produces` / `consumes`、细节能力。
- uBuddy 画像：聚合手下 5 个 Agent 的标签、任务类型和交付物，并加上协调类标签。不另起一套与手下无关的秘书空话。

## 门禁

- 每人恰好 5 个 Agent，职能不少于 3 种，且有近邻位。
- 画像通过 `validateUBuddyCapabilityProfile`。
- 配对没有 `combined` 总分。
- 全量配对不少于 8000，按组织切分 train / development / test。

## 标签来源与强度

| 状态 | 来源 | 能否当 gold |
|---|---|---|
| `prelabel` | 规则预标 `prelabel_v1` | 否，只是待复核草稿 |
| `single` | 1 名真人（train / development 复核） | 是，弱监督 |
| `agreed` | 2 名真人在两轴上完全一致（test） | 是，主金标 |
| `adjudicated` | 2 人不一致后由第 3 人裁决（test） | 是，主金标 |
| `needs_adjudication` | 2 人不一致且未裁决 | 否，不进训练 |

`test` 采用盲标：标注时不显示 AI 预标、参考分和另一位标注员的结果，避免共享锚点制造假一致。一致性以 Cohen κ（5 档）报告；「差不超过一档」只作诊断，不会被合成成一个 gold 值。`apply_labels.mjs` 只导出上面标为「是」的状态。
