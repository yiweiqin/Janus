# Remote OrgBench initialization change manifest

This implementation adds a remote-only initialization path without creating local Windows users or touching a local database.

## Added

- `roster.mjs`: fixed six-user roster, six execution families, stable Agent IDs and public profile templates.
- `remoteInitCore.mjs`: guarded PostgreSQL initialization, Cloud profile publication, grants, artifacts and verification.
- `remoteInit.mjs`: one-shot CLI entry point.
- `verifyRemoteInit.mjs`: independent artifact verification.
- `remoteInit.test.mjs`: no-database safety and manifest tests.
- `Dockerfile.orgbench-init` and `orgbench-init.env.example`: Ubuntu/Docker execution support.

## Updated

- `package.json`: remote init/verify commands and remote tests.
- `deploy/community/compose.yml`: opt-in `orgbench` profile service.
- `orgbench_experiment.mjs`: maps dynamic local Agent IDs and selected uBuddy IDs onto the Cloud identities generated by the initializer.
- `.gitignore`: excludes the real remote initializer env file.

## Safety boundaries

- Refuses Windows execution.
- Requires an explicit remote-write acknowledgement.
- Never reads or writes model API credentials.
- Does not delete users, Agents, profiles, Memory, grants or unrelated data.
- Secret artifacts are written with mode `0600` under the ignored experiment run directory.
